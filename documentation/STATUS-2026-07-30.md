# L++ status — 2026-07-30

This is the current implementation truth for the repository. It supersedes old
reports that described the pre-MIR escape architecture.

## Executive summary

L++ is a Rust compiler that lowers source to MIR and then to native object code.
The production default backend is Cranelift. An optional LLVM backend is also
available through `--backend llvm`.

```text
source
  -> lexer/parser
  -> semantic analysis
  -> type checking + monomorphization
  -> MIR lowering
  -> scalar MIR cleanup passes
  -> cycle breaking
  -> MIR escape solver
  -> stack/ARC/Arena ownership lowering
  -> ARC insertion + move-out
  -> Cranelift (default) or LLVM (optional)
  -> host linker or lpp-link
```

## Current commands

```sh
# Default Cranelift build
lpp program.lpp

# Explicit backend selection
lpp program.lpp --backend cranelift
lpp program.lpp --backend llvm

# Linker selection
lpp program.lpp --backend llvm --linker host
lpp program.lpp --backend llvm --linker direct

# Object output
lpp program.lpp --backend llvm --emit-object

# MIR ownership facts
lpp program.lpp --dump-escape
lpp program.lpp --dump-mir
```

LLVM uses `clang` to assemble textual LLVM IR. Set `LPP_LLVM_CC` when the
compiler is not named `clang`; set `LPP_LLVM_MARCH=native` to request host CPU
features for LLVM output.

## Ownership model

Ownership reachability is computed once over MIR in
`src/mir/escape_solver.rs`:

```text
Frame < Owned < Shared
```

- `Frame`: no pointer can outlive the creating frame; stack payloads are safe.
- `Owned`: ARC-managed single-thread ownership.
- `Shared`: may cross a thread boundary; atomic ARC is used.

Arena is an allocation strategy for self-referential structs, not a fourth
escape-lattice point. Arena nodes retain ARC-compatible headers and a region;
the cycle breaker demotes one edge of each type cycle to non-owning, and the
region is reclaimed after its last node dies.

The old AST escape analyzer was removed. `--dump-escape` now reports MIR facts.

## Vector support

Both backends support explicit two-lane signed integer vectors:

```text
vec_i64x2(a, b)
vec_i64x2_splat(x)
vec_i64x2_add/sub/mul/xor(a, b)
vec_i64x2_shr(v, constant_shift)
vec_i64x2_extract(v, constant_lane)
vec_i64x2_sum(v)
```

`vec_i64_checksum(n)` is a long-workload intrinsic. LLVM emits `<4 x i64>`
vector IR; the Cranelift/runtime path has an AVX2 implementation plus scalar
fallback.

This is explicit vector support. Automatic vectorization of every arbitrary
L++ list loop is not claimed.

## Four-feature experimental first tier

The current tree implements four new vertical slices in the frontend,
typechecker, MIR, both object backends, and all three runtime sources:

- fixed structural `Tuple` types of arity 2–4, tuple construction, return, and
  destructuring; tuple payload metadata drives exact child ARC destruction;
- final typed variadic parameters (`...items: T`), lowered at each call site to
  a `List[T]` rest object; extern declarations continue to reject native C
  varargs;
- stack-resident, zero-copy `StrSlice` and `Slice[T]` views with construction
  and read bounds checks, source generation checks, and a MIR borrow validator;
- `async def` and postfix `.await`, lowered to task environment/state records
  and deterministic single-thread run-to-completion polling. Async `main` is
  entered through the executor wrapper.

The slice first tier rejects return, closure capture, owning aggregate/container
storage, thread handoff, unknown retaining calls, and source reassignment while
a view is live. It permits explicit slice operations and statically known
non-retaining readers with slice-typed parameters. `str_slice_to_str` /
`slice_to_str` is the allocating escape for string views.

The async first tier creates no hidden OS threads. Polling is idempotent after
completion; double-await of a managed result receives a fresh ARC reference.
Dropping an unpolled task releases its environment exactly once. Task capture
by closures is rejected to keep this tier executor-confined. Blocking
file/network/process/input operations are rejected transitively from async call
graphs unless a real adapter is added in a future tier.

Status remains **experimental**, not project-wide feature freeze: readiness
adapters/backpressure and general coroutine suspension are not present, slice
lifetimes are deliberately restrictive, and Windows execution still needs a
real Windows runner.

## Known remaining work

- Async socket/file readiness adapters, backpressure, and general suspension
  points are not implemented; blocking operations remain rejected in async code.
- Borrowed slices intentionally lack general lifetime parameters and mutation;
  the first tier uses conservative non-escape diagnostics.
- Tuple arity above four and native unsafe C varargs are not implemented.
- Windows execution of the new runtime symbols and LLVM objects still needs a
  real Windows CI runner.
- LLVM and Cranelift have separate lowering implementations and must be kept in
  parity when new MIR forms are added.
- General automatic vectorization of arbitrary loops is not implemented.
- Arena allocation currently prioritizes correctness and bulk lifetime handling;
  a bump/chunk allocator is a future measured optimization.
- LLVM LTO/PGO integration is not implemented.

Arena regions, MIR escape analysis, the optional LLVM backend, and the current
runtime/linker paths are implemented. Do not use older documents that claim
`EscapeAnalyzer`, `StorageClass::Arena`, cycle rejection, or an unimplemented
LLVM tier as present-tense facts.
