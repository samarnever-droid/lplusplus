# L++ v0.3.1 Release Notes

**Release Date:** 2026-11-15  
**Milestone:** Multi-Threaded Async Execution, Complete WASM Cycle Collection, Multi-Megabyte WASI File I/O, and WASM `-O3` Spec Compliance

L++ v0.3.1 builds on the `v0.3.0` foundation by eliminating single-threaded async execution limits, finishing deterministic Bacon-Rajan cycle collection on WebAssembly, fixing multi-megabyte WASI filesystem I/O and WASM `-O3` optimization, and repairing Linux release artifact packaging.

---

## Highlights

### 1. Production Multi-Threaded Work-Stealing `async` / `await` Executor
- **Work-Stealing Task Pool**: Replaced single-threaded async execution in `lpp_runtime` (`runtime/lpp_runtime/arc_tasks.inc`, `cycle.inc`, and `crates/lpp-runtime/src/{arc.rs, collect.rs, task.rs}`) with a 64-shard work-stealing pool configurable via `LPP_ASYNC_THREADS`.
- **TSan & ASan Clean Atomic ARC**: Fixed multi-threaded ARC release race conditions via pre-decrement `note_possible_root_buffer` / `lpp__note_possible_root_buffer`, removing legacy unsynchronized root buffering and validating under ThreadSanitizer, AddressSanitizer, LeakSanitizer, and UBSan across 4-thread and 8-thread stress suites.
- **`List[Task[T]]` & Async Ownership Verification**: Added first-class support for spawning and awaiting `List[Task[T]]` collections with `OwnershipBalancePass` enforcement across async suspension boundaries (`crates/lpp-ownership`, `crates/lpp-codegen-cranelift`).

### 2. Full WASM Bacon-Rajan Cycle Collection
- **Tuple Trace Bitmask Fix**: Fixed `emit_trace_tuple` in `crates/lpp-codegen-wasm/src/cycle.rs` to read the 64-bit `managed_mask` from payload offset `0` (matching `lpp_drop_tuple`, `emit_tuple_literal`, and async task environment tuples) and traverse managed fields at `16 + 8*i`.
- **4-Backend Cycle Parity**: Verified deterministic cycle collection and bounded WebAssembly memory growth across structs, enums, closures, and tuples under Cranelift (`-O0`), LLVM (`-O0`, `-O3`), and WASM WASI (`p21b_cycles_all_4` and `cycle_gate` bounded-churn tests).

### 3. WASI Multi-Megabyte `read_file` / `write_file` / `append_file` Correctness
- **Removed Silent 4 KiB Truncation**: Rewrote `read_file` in `crates/lpp-codegen-wasm/src/helper_body/io.rs` to query file length via `fd_seek(END)`, allocate an exact ARC string buffer, and loop `fd_read` until full EOF instead of truncating at a 4,096-byte chunk.
- **Reliable Partial-Write Handling & Imports**: Updated `write_file` and `append_file` to loop `fd_write` until all bytes are flushed with proper error reporting on zero-progress writes, and ensured `fd_write` is always imported even in WASI modules that do not call `print*`. Verified end-to-end in Node WASI across `0`, `4095`, `4096`, `4097`, `1 MiB`, and `8 MiB` payloads.

### 4. WASM Spec-Compliant `name` Section & Working `-O3` Optimization
- **Spec-Compliant `name` Section**: Fixed subsection 1 function-name entries in `crates/lpp-codegen-wasm/src/wasm_compile.rs` to encode the LEB128 `funcidx` before the name string per the WebAssembly Core Specification, verified with `wasmparser::KnownCustom::Name`.
- **Binaryen `wasm-opt -O3` Support**: Added `--enable-bulk-memory` to the `wasm-opt` invocation in `crates/lpp-codegen-wasm/src/lib.rs` so single-command `lpp ... --target wasm32-wasip1 -O3` builds succeed cleanly.

### 5. Tooling, Debug Metadata & Release Pipeline Fixes
- **Dynamic Package Version in Debug Metadata**: `crates/lpp-codegen-llvm/src/lower/debug.rs` now embeds `env!("CARGO_PKG_VERSION")` dynamically instead of a hardcoded version string.
- **Linux Release Packaging Fix**: Updated `.github/workflows/release.yml` to copy `liblpp_net_runtime.a` from the workspace target directory (`target/x86_64-unknown-linux-musl/release/liblpp_net_runtime.a`), fixing the `v0.3.0` Linux release tarball build failure.
