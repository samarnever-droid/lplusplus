# L++ v0.2.0 release brief

## Release coordinates

- Public release name: **L++ v0.2.0**
- Git tag: **`v0.2.0`**
- Cargo workspace version: **`0.2.0`**
- Preceding rewrite tag: **`v0.1`**

## Highlights since `v0.1`

### 1. Native engine cutover & modular backend architecture
- Unconditional cutover to `RewriteEngine` (`src/main.rs`), retiring `LegacyEngine`.
- Modularized code generation backends (`crates/lpp-codegen-cranelift`, `crates/lpp-codegen-llvm`, `crates/lpp-codegen-wasm`) behind `crates/lpp-codegen-api`.
- Standardized 16-byte common native ARC header for destructor-free objects/strings and 24-byte prefix for destructor-bearing native objects.

### 2. Memory reclamation, tuples, and MIR verification (`3fdb0dc`)
- Bacon-Rajan trial-deletion cycle collector for native Cranelift `Shared` cycle-capable types, paired with MIR ARC leak oracle checks (`E4304`).
- Structural tuples (arity 2–4) with managed elements and Cranelift tuple drop/trace glue (`lpp_drop_t{n}` / `lpp_trace_t{n}`).
- Strict compatibility freeze verification (`scripts/check_compatibility_freeze.py`).

### 3. External C FFI, SIMD kernel, MIR inlining (`--lto`), and PGO (`37f6972`)
- Direct non-variadic `extern "C"` calls on Cranelift for supported scalar types (`Bool`, `Int`, `Float`, `U8`/`I8`, `U16`/`I16`, `U32`/`I32`) and borrowed `Str`, including cross-module imported declarations and `-l <lib>` propagation.
- Runtime `vec_i64_checksum` auto-dispatching to a 4-lane 256-bit AVX2 kernel on capable x86-64 hosts with scalar fallback.
- Bounded whole-program pure scalar MIR inliner (`--lto`) and Cranelift host-target function-entry profiling (`--pgo-generate` / `--pgo-use`).

### 4. Builtins & WASI WebAssembly filesystem support (`e3f674d`, `4e17c16` + completion)
- Added CLI argument helpers (`args`, `args_count`, `args_get`), filesystem/fd/positional I/O, JSON handle helpers, and ergonomic string builtins.
- Completed WASI WebAssembly lowering in `crates/lpp-codegen-wasm` for `file_exists`, `read_file`, `write_file`, `append_file`, and `delete_file` (`remove_file`) over WASI preopens.

### 5. Keel & package registry hardening (`afef81f`)
- Hardened Git registry transport, switched default registry configuration to `llppregistry`, and added published archive checksum/integrity verification.

### 6. Documentation & workspace cleanup
- Removed duplicate `crates/lpp-runtime` entry in `Cargo.toml` `default-members`.
- Enforced LF line endings in `.gitattributes` for `.lpp`, `.tsv`, `.expected`, `.snap`, `.symbols`, and `.h` files so Windows checkouts match strict snapshot, ABI, and WASI stdout checks.
- Updated `specs.md`, `AGENTS.md`, `ARCHITECTURE.md`, `PPP.md`, `ROADMAP.md`, `documentation/CURRENT_CAPABILITIES.md`, and `wiki/` to match the current `crates/` workspace, `Keel.toml` manifest model, and verified safety/backend boundaries.

## Known limitations (carried transparently in `v0.2.0`)

- **WASM cycle collection**: WASM reuses freed blocks for acyclic churn, but does not collect unreachable reference cycles.
- **LLVM backend**: Experimental scalar/direct-call subset (`x86_64`); managed structs/lists/tuples and cycle-collector parity remain incomplete.
- **Concurrency safety**: Native ARC refcounts are atomic, but `Send`/`Sync`-style compile-time enforcement and TSan verification remain open (`documentation/CONCURRENCY.md`).
- **Toolchain targets**: No arbitrary cross-OS sysroots; `extern "C"` remains limited to the documented scalar/`Str` Cranelift subset (`documentation/EXTERNAL_C_ABI.md`).

For the full capability matrix and roadmap, see [`specs.md`](../../specs.md), [`documentation/CURRENT_CAPABILITIES.md`](../../documentation/CURRENT_CAPABILITIES.md), and [`ROADMAP.md`](../../ROADMAP.md).
